# Кодекс поведения участников

## Принципы

Sign-Craze — открытый технический проект для пользователей и разработчиков
сетевых инструментов на роутерах Keenetic. Сообщество строится вокруг
технического содержания: качество кода, воспроизводимость багов,
обоснованность решений.

Кодекс задаёт минимальные правила взаимодействия, чтобы дискуссии оставались
продуктивными, а вклад — безопасным для всех участников и для пользователей,
устанавливающих утилиту на свои роутеры.

## Ожидаемое поведение

- **По существу.** Аргументы технические: код, логи, спецификация,
  вывод `sign-craze --diag` или `support-bundle`. Без переходов на личность.
- **Воспроизводимость.** При обсуждении бага — версия sign-craze, модель
  роутера, архитектура (`mipsle`/`mips`/`arm`/`arm64`), команда, минимальный
  пример, ожидаемый и фактический результат.
- **Уважение к чужому времени.** Перед открытием issue — поиск по
  существующим, чтение wiki и FAQ. PR — с тестами, без отладочного мусора,
  с понятным описанием мотивации.
- **Конструктивная критика.** Ревью обсуждает код, а не автора. Замечания
  формулируются как предложения с обоснованием, а не как претензии.
- **Признание ошибок.** Сломал — откатил, объяснил причину, поправил.
  Без попыток скрыть регресс.

## Неприемлемое поведение

- **Личные нападки** — оскорбления, унижения, угрозы, преследование.
  В том числе по техническим темам: «ты не разбираешься», «уходи из проекта».
- **Домогательства** — навязчивые сообщения, нежелательные контакты после
  явного отказа, публикация чужих личных данных (адреса, телефоны,
  частная переписка) без согласия.
- **Раскрытие чужих данных проекта** — публикация фрагментов чужих логов,
  IP‑адресов клиентов LAN, MAC, WAN IP роутера, токенов и URL outbound
  (sing-box `proxy.json`), API‑ключей провайдеров без согласия владельца.
  Перед публикацией логов — редактируйте чувствительные поля.
- **Вредоносный или недобросовестный вклад** — бэкдоры, скрытая телеметрия,
  обфусцированный код, обход BSD‑3‑Clause, заимствование исходников
  XKeen или иных закрытых/несовместимых по лицензии проектов в обход
  clean‑room политики.
- **Спам и оффтоп** — реклама, подмена технической дискуссии политикой,
  религией или иными нерелевантными темами; повторное открытие закрытых
  issue без новой технической информации.
- **Сексуализированный контент** в любых каналах проекта.

Кодекс действует во всех пространствах проекта:

  e‑mail с проектного адреса)

## Уязвимости безопасности

Sign-Craze управляет firewall, маршрутизацией и Web UI на роутере
домашней сети. Уязвимости (повышение привилегий, bypass правил,
утечка ключей, RCE через `:9090`/`:9091`/`:9092`, инъекции в шаблоны
sing-box) сообщайте **приватно**:

- GitHub Security Advisories: <https://github.com/kittylabassistant/sign-craze/security/advisories>

Не открывайте публичный issue до согласования сроков раскрытия
с мейнтейнером.

## Сообщить о нарушении

Случаи нарушения кодекса:

- GitHub: [@kittylabassistant](https://github.com/kittylabassistant) — приватно, не через
  публичный @‑mention в issue

В сообщении: ссылка на инцидент (URL комментария/PR/коммита),
краткое описание, ваши пожелания по реакции. Конфиденциальность
заявителя гарантируется.

## Применение

Мейнтейнер рассматривает каждый случай отдельно с учётом контекста
и тяжести нарушения. Возможные меры по нарастающей:

1. **Личное замечание.** Письменное объяснение, что именно неприемлемо
   и почему. Просьба отредактировать или удалить материал.
2. **Публичное предупреждение.** Если личное замечание проигнорировано
   или нарушение публичное и затрагивает других участников.
3. **Временная блокировка.** Запрет взаимодействия с проектом на срок
   от 7 до 90 дней. Применяется при систематических или серьёзных
   нарушениях.
4. **Постоянная блокировка.** Бан в репозитории и связанных каналах.
   Применяется при злонамеренном вкладе (бэкдоры, попытки
   компрометации пользователей), угрозах, преследовании или
   повторных нарушениях после временной блокировки.

Решения мейнтейнера могут быть оспорены тем же каналом
1 месяца.
